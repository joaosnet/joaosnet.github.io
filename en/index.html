fig. 02 · busMethod

Built in short, verifiable cycles.

Every cycle ends with something you can open, test and approve before the next one starts.

  1. Cycle 01 Specification & modeling Turn the problem into a written scope with explicit limits and risks.

    Deliverables

    • Scope with acceptance criteria per feature
    • Architecture diagram and API contracts (OpenAPI)
    • List of risks, dependencies and what stays out

    Acceptance criterionYou sign off the written scope before any code is written.

  2. Cycle 02 Low-level architecture Define data, interfaces and failure modes before writing business logic.

    Deliverables

    • Data schema and migration plan
    • Interfaces between device, backend and UI
    • Logging, metrics and alerting plan

    Acceptance criterionEvery interface has documented and reviewed failure cases.

  3. Cycle 03 Incremental prototyping Small, working increments in an environment you can open yourself.

    Deliverables

    • Weekly increments on a staging environment
    • Reproducible environment with Docker Compose
    • Continuous integration with automated tests

    Acceptance criterionEvery increment passes CI and runs on staging.

  4. Cycle 04 Audit & handover Review security, performance and accessibility, then hand the system over.

    Deliverables

    • Audit of dependencies, secrets and permissions
    • Performance and accessibility measurement with report
    • Operations documentation and handover session

    Acceptance criterionFinal acceptance checklist signed with the report attached.
